# MesclaInvest

Project developed for the **Integrator Project 3** course in Software Engineering at **PUC-Campinas** (2026).

---

## About

MesclaInvest is a mobile platform for **simulated startup investment** linked to the Mescla innovation ecosystem at PUC-Campinas.

Users can browse registered startups, consult corporate information, and participate in a **simulated token trading desk** representing ownership stakes in innovative projects. All financial operations are fully simulated — no real assets or external financial systems are involved.

### Key features

- **Authentication** — registration with email, CPF and phone number; password recovery; optional multi-factor authentication (MFA)
- **Startup catalog** — listing with filters by stage (New, Operating, Expanding), detailed profile with executive summary, ownership structure and public documents
- **Token trading desk** — simulated buy and sell of tokens between registered users, with a fictional BRL digital wallet
- **Value dashboard** — graphical tracking of token value changes over daily, weekly, monthly, last 6 months and YTD periods
- **Q&A with founders** — public or private questions (investors only)

## Running locally (dev environment)

### Prerequisites

- [Flutter SDK](https://docs.flutter.dev/get-started/install)
- [Node.js LTS](https://nodejs.org/)
- [Firebase CLI](https://firebase.google.com/docs/cli) — `npm install -g firebase-tools`
- Android Studio or VS Code with the Flutter extension
- A configured Android/iOS emulator, a physical device, or a browser (for web)

---

### 1. Clone the repository

```bash
git clone https://github.com/eduardokairalla1/ES-PI3-2026-T3-G16.git
cd ES-PI3-2026-T3-G16
```

### 2. Configure environment variables

#### Frontend (`frontend/app/.env`)

Copy the example file and adjust as needed:

```bash
cp frontend/app/.env.example frontend/app/.env
```

| Variable | Description | Dev value |
|---|---|---|
| `USE_EMULATOR` | Connect to local Firebase emulators instead of production | `true` |
| `EMULATOR_HOST` | Host where the emulators are running | `localhost` |
| `AUTH_EMULATOR_PORT` | Firebase Auth emulator port | `9099` |
| `FUNCTIONS_EMULATOR_PORT` | Cloud Functions emulator port | `5001` |
| `FIRESTORE_EMULATOR_PORT` | Firestore emulator port | `8080` |
| `STORAGE_EMULATOR_PORT` | Firebase Storage emulator port | `9199` |

> Set `USE_EMULATOR=false` to point the app at the real Firebase project (production).

---

### 3. Start the backend (Firebase Emulators + Functions)

A single command installs dependencies, compiles TypeScript, starts the file watcher and spins up all emulators:

```bash
cd backend
npm run dev
```

The Firebase Emulator Suite UI will be available at `http://localhost:4000`.

#### Populating the emulators with seed data (optional)

With the emulators running, open a second terminal and run from the `backend` directory:

```bash
# Seed everything at once
npm run seed:all

# Or seed individual collections
npm run seed:startups
npm run seed:users
npm run seed:investments
npm run seed:orderbook
npm run seed:questions
npm run seed:notifications
```

> `seed:all` runs the scripts in dependency order. Run it once after starting the emulators for a fully populated local environment.

---

### 4. Set up the frontend

```bash
cd frontend/app
flutter pub get
```

Make sure the file `lib/firebase_options.dart` is present (generated by FlutterFire CLI). If it is missing:

```bash
flutterfire configure
```

---

### 5. Run the app

**On a connected Android/iOS device or emulator:**

```bash
cd frontend/app
flutter run
```

**In the browser (web server mode):**

```bash
cd frontend/app
flutter run -d web-server --web-port 9000
```

The app will be accessible at `http://localhost:9000`.

**List available devices:**

```bash
flutter devices
```
